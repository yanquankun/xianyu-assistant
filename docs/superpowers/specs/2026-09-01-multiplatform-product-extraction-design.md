# 淘宝、天猫与京东商品解析增强设计

## 1. 背景

当前扩展已经能够接收淘宝、天猫和京东商品链接，但现有解析实现主要依赖通用结构化数据和少量固定 DOM 选择器。真实京东移动商品页可能没有 JSON-LD 或 Open Graph 商品字段，价格还可能使用私有字体字形展示；当前实现因此可能只得到标题，价格、描述和商品图为空，却仍提示解析成功。

本次改动先稳定支持淘宝、天猫、京东三个已知平台。目标不是为三个平台各复制一套完整 DOM 抓取器，而是建立统一的“证据采集、平台适配、字段合并、质量校验”管线，仅把无法通用化的平台差异放进小型适配器。

本设计是对现有商品链接解析流程的增量替换。最终发布仍必须由用户手动完成；未在本文修改的 AI 配置、闲鱼登录检测、草稿编辑、媒体上传和运行记录约束继续有效。

## 2. 目标与验收口径

### 2.1 目标

- 将天猫从淘宝的隐式分支提升为独立平台类型，同时继续共享淘宝域名族的短链安全边界。
- 统一采集结构化数据、Meta、页面语义节点、平台内嵌状态和商品媒体等证据。
- 根据字段级证据的来源、SKU 归属、语义标签和可信度合并标题、价格、原价、描述和图片。
- 正确处理京东私有价格字形、延迟加载商品图、分享短链和已经打开的同商品标签页。
- 解析证据不足时返回明确的“不完整”结果，不能把只得到标题的页面误报为完整成功。
- 将侧边栏、扩展描述和相关文档中的平台文案统一为“淘宝、天猫与京东”。

### 2.2 非目标

- 不构建任意电商平台都能零配置接入的通用抓取器。
- 不依赖 AI 猜测价格、原价、SKU 或媒体地址。
- 不从推荐商品、猜你喜欢、其他规格或评论区补齐当前商品字段。
- 不自动导入来源商品视频；本地视频上传能力保持原有行为。
- 不绕过登录、验证码、风控或平台权限控制。
- 不保存 Cookie、账号信息、完整页面 HTML、完整脚本或完整分享文案。

## 3. 总体架构

解析链路统一为：

1. 输入解析：从纯链接或分享文案中提取第一个有效 HTTP(S) URL。
2. 平台与域名族识别：识别淘宝、天猫、京东、短链及允许的跳转范围。
3. 标签页解析：复用同商品已打开标签页，或创建临时标签页完成安全跳转。
4. 通用证据采集：读取 JSON-LD、Open Graph、普通 Meta、页面标题、语义商品节点和候选图片。
5. 平台适配：读取当前平台特有的内嵌状态、价格展示和商品图库。
6. 字段合并：按 SKU 一致性、语义标签、来源和可信度选择每个字段。
7. 质量校验：校验标题、价格、图片和页面状态，输出警告或失败。
8. 草稿创建：只把通过校验的字段写入 `ProductDraft`，保留字段警告和规范商品链接。

通用采集器不包含淘宝、天猫或京东专用 CSS 选择器。平台差异集中在适配器中，适配器只返回证据，不直接决定最终草稿字段。

## 4. 平台、域名族与商品身份

### 4.1 平台类型

平台类型调整为：

```ts
type ProductPlatform = 'taobao' | 'tmall' | 'jd' | 'generic';
```

- `taobao.com` 商品页识别为 `taobao`。
- `tmall.com` 商品页识别为 `tmall`。
- `jd.com` 商品页识别为 `jd`。
- 未匹配三个已知平台、但仍经过现有安全校验的页面使用 `generic`；`generic` 不获得已知平台的专用解析能力。

平台类型与域名族分开建模：

- 淘宝域名族：`e.tb.cn`、`taobao.com`、`tmall.com`。
- 京东域名族：`3.cn`、`jd.com`。

`e.tb.cn` 可以安全跳转到淘宝或天猫，但最终平台必须根据稳定后的商品页域名确定。草稿和运行记录分别显示“淘宝来源”“天猫来源”或“京东来源”。

### 4.2 商品身份

链接比较不能使用包含跟踪参数和分享参数的完整 URL 字符串。解析器为已知平台提取稳定的商品身份：

```ts
interface ProductIdentity {
  platform: 'taobao' | 'tmall' | 'jd';
  productId: string;
  skuId?: string;
  canonicalUrl: string;
}
```

- 商品身份只能由受支持的商品路由和严格校验后的商品标识构造。
- `productId` 表示平台商品主标识；链接或页面能可靠给出规格标识时再记录 `skuId`，不能把淘宝商品 `id` 一律当成规格标识。
- `canonicalUrl` 删除广告参数、跟踪参数、分享参数和 hash，保留确定商品与必要规格所需的参数。
- 两个标签页的平台和 `productId` 一致，且请求中明确存在的 `skuId` 不冲突时，才视为可复用；仅 URL 文本相似不能作为复用依据。
- 无法提取稳定商品身份时，保留规范化 URL 比较作为后备，但不得跨平台复用标签页。

## 5. 证据模型与合并规则

### 5.1 字段证据

采集器与适配器输出字段级证据，至少包含：

```ts
type EvidenceSource =
  | 'json-ld'
  | 'open-graph'
  | 'meta'
  | 'semantic-dom'
  | 'embedded-state'
  | 'platform-gallery';

interface FieldEvidence<T> {
  value: T;
  source: EvidenceSource;
  skuId?: string;
  label?: string;
  confidence: 'high' | 'medium' | 'low';
}
```

价格证据还必须记录货币、价格语义和展示条件；图片证据还必须记录原始地址、候选高清地址和所在图库位置。证据合并器按字段分别选择，不以“整个解析器优先级”覆盖所有字段。

高可信证据必须满足：

- 能绑定到当前商品或当前 SKU；
- 数据类型和格式合法；
- 来源节点具有明确商品语义；
- 不来自推荐、广告、其他规格、评价或店铺内容。

发生高可信证据冲突时，不静默选择看似更低或更高的数值；使用规定的来源优先级选择，并向草稿追加可见警告。

### 5.2 标题

标题按以下顺序选择：

1. 与当前 SKU 绑定的平台内嵌状态标题。
2. JSON-LD `Product.name`。
3. 平台适配器确认的商品主标题语义节点。
4. Open Graph 标题。
5. 清洗后的页面标题。

清洗只移除已知平台后缀、重复空白和展示性分隔符。不能直接使用页面中的第一个 `h1`，也不能把登录、错误、风控或活动页标题作为商品标题。

标题是创建解析草稿的必填字段。标题为空时解析失败；只有在已确认是有效商品路由和正常商品页时，才允许使用分享文案中书名号内的标题作为后备，并添加“标题来自分享文案，请核对”的警告。

### 5.3 售价与原价

每条价格证据必须包含：

```ts
type PriceKind = 'sale' | 'original' | 'conditional' | 'unknown';

interface PriceEvidence extends FieldEvidence<number> {
  currency: 'CNY';
  kind: PriceKind;
  condition?: '到手价' | '券后价' | '会员价' | string;
}
```

规则如下：

- 售价必须是当前商品、当前 SKU 的页面主价格。
- 明确标注“到手价”“券后价”“会员价”等条件的价格可以作为售价，但必须保留条件标签并显示“价格含条件，请发布前核对”的警告。
- 原价只接受明确标注为原价、划线价、市场价等语义的当前 SKU 价格，并且必须大于售价。
- 不把价格区间的任意一端、推荐卡片价格、其他规格价格或来源不明的数值推断为当前售价。
- 高可信价格之间冲突时，以当前 SKU 的平台主价格证据优先，并显示冲突警告。
- 无可靠售价时保持为空；AI 扩写不能补写售价或原价。

京东适配器可以处理私有字体价格，但必须遵循以下限制：

- 只读取与当前商品主价格区域或当前 SKU 内嵌状态紧密绑定的数值。
- 只允许解析严格白名单字段或可验证的字形映射，禁止执行页面脚本、`eval` 或任意表达式。
- 解析后的值必须是有限、正数、合理小数位的人民币金额。
- 无法证明字段属于当前 SKU 时放弃该证据，不能从同 SKU 推荐卡片反推主价格。

### 5.4 描述

描述按以下顺序选择：

1. JSON-LD `Product.description`。
2. Open Graph 描述。
3. 普通 `meta[name="description"]`。
4. 平台适配器确认的商品摘要。

描述清洗移除平台登录提示、促销模板、导航文本、店铺口号和重复标题，保留商品事实。来源页没有可靠描述时允许留空；现有 AI 扩写流程可以基于已解析事实生成闲鱼描述，但生成内容必须继续接受现有事实校验，不能反向成为解析证据。

### 5.5 图片

图片证据按以下范围采集：

- 通用结构化数据中的当前商品图片。
- Open Graph 当前商品图片。
- 平台适配器确认的当前 SKU 主图库。

平台图库优先读取可验证的高清延迟加载属性，例如京东图库中的高清后备地址；图片处理必须：

- 排除占位图、图标、头像、评价图片、店铺图片、推荐商品和其他规格图片。
- 统一协议、移除纯展示尺寸参数，并按规范 CDN 地址去重。
- 保持商品图库顺序，最多输出 9 张候选图。
- 不从视频封面推断商品图，也不自动导入来源商品视频。

单张图片下载失败仍保留其他有效图片并产生警告。没有可靠图片时草稿图片数组为空。

## 6. 页面解析与标签页复用

### 6.1 完整商品链接

1. 规范化输入 URL，并识别平台和商品身份。
2. 在当前窗口及已打开标签页中查找同平台、同商品标识的正常商品页。
3. 找到时直接在该标签页采集证据，不创建重复标签页。
4. 未找到时创建后台临时标签页，并只授予当前平台解析所需的最小主机权限。

### 6.2 分享短链

1. 先在对应短链域名族内创建临时标签页完成跳转。
2. URL 稳定后识别最终平台、商品身份和规范商品 URL。
3. 若已有同商品正常标签页，关闭临时标签页并复用已有标签页。
4. 否则继续在临时标签页解析，完成后关闭。

短链不能跨域名族跳转。淘宝域名族短链跳到京东、京东短链跳到淘宝或天猫，以及跳到登录、验证码、风控和非商品路由时立即失败。

### 6.3 语义就绪

不能继续使用固定的 `complete + 800ms` 作为唯一等待条件。页面就绪需要同时满足：

- 标签页加载状态为 `complete`，且 URL 在安静窗口内不再变化；
- URL 是受支持的平台商品路由；
- 页面未命中登录、验证码、风控、错误或系统繁忙特征；
- 至少出现商品主容器、当前商品内嵌状态或结构化商品数据之一。

到达上限仍未满足时返回“商品页面尚未准备完成”，不得继续用页面标题创建伪商品。

## 7. 结果状态、警告与错误

解析结果按以下质量门槛处理：

- 标题为空：解析失败，不创建草稿。
- 标题存在，但售价和图片同时为空：返回“解析不完整”，不显示“商品信息已解析”，允许用户重试或手动填写。
- 仅售价为空或仅图片为空：允许创建草稿，但在表单顶部和对应字段附近显示明确警告。
- 条件价格、价格冲突、使用分享标题、图片不足或部分图片失败：允许创建草稿，并将警告写入草稿与运行记录。
- 登录、验证码、风控、错误页、跨域名族跳转或非商品路由：解析失败，给出可操作错误，不进入字段合并。

错误信息区分“需要登录”“需要人工完成验证”“页面不是商品页”“页面尚未准备完成”“字段证据不足”和“权限未授予”。错误信息不得包含 Cookie、Token、页面脚本或完整分享参数。

## 8. 安全与日志

- 平台内嵌状态只读取严格白名单路径，并使用 JSON 解析；不得执行页面返回的代码。
- 不读取 Cookie、Local Storage 中的账号数据、订单数据或与商品解析无关的完整页面状态。
- 主机权限继续按解析操作按需申请，不扩大为永久全站权限。
- 运行记录只保存平台、规范商品 URL、字段完成情况、警告和安全错误摘要。
- 不保存完整 DOM、完整脚本、原始私有字形数据、账号标识、授权信息或带分享参数的完整 URL。
- 日志中的 URL 继续删除用户名、密码、跟踪参数和敏感查询参数。

## 9. UI 与文案

侧边栏商品链接入口统一使用以下文案：

- 平台标题：`淘宝、天猫与京东`
- 输入提示：`粘贴淘宝、天猫或京东商品链接`
- 空闲状态提示：`粘贴淘宝、天猫或京东商品链接开始整理`

扩展清单、包描述和用户文档中涉及支持平台的文字同步加入天猫。解析完成后按独立平台类型显示“淘宝来源”“天猫来源”或“京东来源”。

警告必须直接说明缺失字段或条件，例如“未能可靠识别售价，请手动填写”“仅识别到标题，价格和商品图均缺失，请重试或手动填写”，不能只显示抽象置信度。

## 10. 兼容性与迁移

- 消息类型验证、草稿验证、持久化读取和 UI 平台映射均接受 `tmall`。
- 旧版本把天猫保存为 `taobao`，且没有独立迁移标记。恢复旧草稿时，如果其规范商品 URL 可确认属于 `tmall.com`，在内存迁移中改为 `tmall` 并按新格式保存。
- 旧草稿没有规范 URL、URL 非法或域名不能确认时保持原平台值，不凭标题或图片域名猜测。
- 已有淘宝和京东草稿、运行记录及消息继续兼容；旧运行记录不补造平台或字段证据。
- `ParsedProduct` 和草稿继续不包含来源商品视频，避免与现有本地视频模型混淆。

## 11. 实施拆分

### 11.1 类型与平台识别

- 扩展 `ProductPlatform`、消息验证和持久化迁移。
- 分离最终平台与安全域名族。
- 增加规范商品 URL 和商品身份解析。

### 11.2 证据采集与合并

- 将现有解析输出改为字段证据。
- 实现通用 JSON-LD、Open Graph、Meta 和语义候选采集。
- 实现 SKU 校验、字段优先级、冲突警告和质量门槛。

### 11.3 平台适配器

- 淘宝适配器：当前商品状态、主价格语义和商品图库。
- 天猫适配器：独立平台识别、当前商品状态、主价格语义和商品图库。
- 京东适配器：当前 SKU 状态、私有价格字形或白名单价格数据、延迟加载商品图库。

每个适配器只处理当前平台无法由通用采集器稳定获得的证据，禁止复制完整通用流程。

### 11.4 标签页与 UI

- 用商品身份复用同商品标签页。
- 用语义就绪替换固定延迟。
- 补充不完整状态、字段警告和淘宝/天猫/京东统一文案。

## 12. 测试与验收

### 12.1 自动化测试

新增或更新以下测试：

- 同一域名族内正确区分淘宝和天猫，`e.tb.cn` 可落到两者但最终类型准确。
- 标题按内嵌状态、JSON-LD、语义节点、Open Graph、页面标题依次回退。
- 当前 SKU 与推荐商品、其他规格严格隔离。
- 条件售价保留标签并产生警告，原价只有明确语义且大于售价时写入。
- 京东私有价格展示能够由允许的当前 SKU 证据解析；无法绑定 SKU 时保持为空。
- 京东延迟加载图库优先高清地址，排除推荐图、占位图并规范化去重。
- 分享短链跳转后能够复用已经打开的同商品标签页。
- 登录、验证码、风控、错误页、跨域名族跳转和非商品路由失败。
- 标题为空失败；售价和图片同时为空返回不完整；单字段缺失允许带警告创建草稿。
- 旧天猫草稿仅在规范 URL 可确认时迁移为 `tmall`。
- 侧边栏、初始状态、扩展清单、包描述和文档中的平台文案包含淘宝、天猫与京东。

先运行解析器、标签页等待、消息验证、状态和持久化相关的定向测试，再运行仓库完整测试、类型检查和构建。

### 12.2 真实页面验收

在用户已经正常登录的平台页面中，每个平台至少验证：

- 1 个普通单规格商品；
- 1 个促销或多规格商品；
- 对应完整链接和分享短链。

逐项核对标题、售价、条件价格标签、显式原价、描述、图片数量与顺序、平台来源和警告。京东验收必须覆盖私有价格字形和延迟加载图库。测试过程中不点击闲鱼最终发布按钮，来源商品视频不得进入草稿。

### 12.3 完成标准

- 三个平台的正常样本不会再出现“只有标题却提示完整解析成功”。
- 字段值可以追溯到当前商品的明确证据，价格和媒体不由 AI 或推荐内容补造。
- 自动化测试、类型检查和构建通过。
- 真实页面验收结果记录已验证样本、缺失字段和平台限制；未覆盖的页面形态不能宣称已稳定支持。
