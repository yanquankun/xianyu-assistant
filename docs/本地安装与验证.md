# 本地安装与验证

## 目标

本文说明如何在本机生成、加载和验证闲鱼上架助手。验证分为自动化夹具测试和真实浏览器人工检查两部分；自动化测试不访问真实淘宝、京东短链或闲鱼账号，人工检查也必须停在最终发布之前。

## 前置条件

- macOS、Windows 或 Linux 桌面环境
- Chrome 116 或更高版本
- Node.js 22 或更高版本
- pnpm 11.19.0
- 如需验证 AI：一个支持 OpenAI Chat Completions 格式的接口地址、API Key 和模型名称
- 如需验证闲鱼填表：已经由用户本人登录的闲鱼网页账号

不要把真实 API Key 写入源码、`.env`、截图、Issue 或提交记录。

## 安装依赖

在项目根目录执行：

```bash
pnpm install
```

确认运行环境：

```bash
node --version
pnpm --version
```

## 开发模式

执行：

```bash
pnpm dev
```

WXT 会生成开发构建并监听文件变化。正常输出目录为：

```text
dev-dist/xianyu-assistant-unpacked
```

第一次启动后，在日常 Chrome 中操作：

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择 `dev-dist/xianyu-assistant-unpacked`。
5. 保持 `pnpm dev` 运行。

后续修改源码时不需要重新选择目录。WXT 会持续监听文件：侧边栏页面使用热更新，后台脚本、内容脚本或 Manifest 发生变化时会重新构建并重新加载扩展。结束开发服务时在终端按 `Ctrl+C`。

## 加载生产构建

如需在“加载已解压的扩展程序”中检查生产构建，执行：

```bash
pnpm build:unpacked
```

然后在 Chrome 中操作：

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择项目中的 `dist/xianyu-assistant-unpacked` 目录，不要选择 `dist` 根目录、CRX 或 ZIP 文件。
5. 确认扩展列表中出现“闲鱼上架助手”。
6. 可在 Chrome 扩展菜单中固定该扩展，便于打开侧边栏。

点击扩展工具栏图标后应打开 Chrome 原生侧边栏。侧边栏位于左侧还是右侧由 Chrome 控制；扩展无法强制位置。如果它出现在左侧，可在 Chrome 侧边栏设置中切换。

## 配置 OpenAI 兼容接口

1. 打开扩展侧边栏，进入“AI 配置”。
2. 填写 Base URL、API Key 和 Model。
3. 按需调整 Temperature 和补充要求。
4. 点击“测试连接”。
5. 连接成功后点击“保存配置”。

请求目标会规范化为：

```text
Base URL/chat/completions
```

远程接口必须使用 HTTPS。本机夹具或本地模型服务使用 `localhost`、`*.localhost`、`127.0.0.1` 或 `::1` 时可以使用 HTTP。

首次访问该接口来源时，Chrome 可能显示站点访问授权。扩展只在用户操作时请求当前 Base URL 的精确来源。拒绝授权后不会发送请求，也不会清空草稿。

如果出现“AI 接口认证失败”，检查 API Key；如果出现“AI 响应缺少 choices”或“AI 文案不是有效 JSON”，说明服务端返回格式不兼容。扩展需要兼容 OpenAI Chat Completions 的 `choices[0].message.content`，扩写内容还必须是包含 `title` 和 `description` 的 JSON 对象。

## 验证商品解析与分享文案

1. 在普通标签页打开一个公开可访问的淘宝、天猫或京东商品页。
2. 把完整 URL 粘贴到侧边栏“商品链接”。也可以粘贴淘宝、京东客户端生成的完整分享文案，其中必须包含合法 HTTP(S) 链接。
3. 点击“解析商品”。
4. 如 Chrome 询问是否允许访问该站点，核对域名后再授权。
5. 检查标题、售价、原价、描述和图片。
6. 取消选择不需要上传的图片，并手动修正缺失或错误信息。

验证分享文案和短链时，继续检查以下边界：

1. `3.cn` 只能跳转到京东域名族，`e.tb.cn` 只能跳转到淘宝或天猫域名族。
2. 成功后草稿和运行记录快照应分别保留用户提交链接与最终规范商品链接；需要工程验收时，可在扩展开发者工具中检查 `productDraft.submittedUrl`、`productDraft.canonicalUrl` 和 `operationLogs[].details.draft`。
3. 页面没有标题但确认为有效商品路由时，可以使用分享文案中的 `「标题」`，并显示“标题来自分享文案，请核对”。
4. 分享码不能成为标题；HTTP 400/403/404/500、页面不存在、访问出错、登录和验证页必须拒绝，且不能创建错误草稿。

建议先打开商品页再执行解析。这样扩展会优先复用现有页面，既便于处理站点登录或验证码，也不会额外打开临时标签页。

页面结构变化、登录重定向、反爬验证和区域限制都可能导致字段缺失。遇到解析失败时，先检查商品页是否能在当前浏览器中正常显示，再查看侧边栏“运行记录”。

如果不需要解析来源链接，可以点击“手动填写”创建空白草稿。编辑区右上角应显示步骤 `02`。手动输入的标题、描述和价格会保存在扩展本地存储，关闭并重新打开侧边栏后可以恢复，再继续执行 AI 扩写。没有至少一张已选择图片时，“填入闲鱼”会保持禁用。

## 验证本地图片和媒体预览

1. 进入解析草稿或手动草稿，点击“上传图片”。
2. 一次选择多张 JPEG、PNG 或 WebP；确认合法图片批量加入，已选数量不超过 9 张。
3. 验证单张超过 10 MB、已选本地图片总量超过 20 MB 或第 10 张图片被拒绝，已有草稿不丢失。
4. 点击图片缩略图，确认顶层预览对话框可以通过关闭按钮、遮罩空白处和 Escape 关闭，且预览不会改变选择状态。
5. 关闭并重新打开侧边栏，确认本地图片元数据和 IndexedDB 文件仍可读取。
6. 删除本地图片后重新打开侧边栏，确认该图片不再恢复。

本地媒体只保存在当前扩展域的 IndexedDB 中。`unlimitedStorage` 用于提高扩展本地存储配额，不会放宽 9 张、单图 10 MB、图片总量 20 MB 和单视频 100 MB 的应用限制。

## 验证返回选择方式

1. 在空白手动草稿中点击“返回选择方式”，确认直接回到步骤 `01` 的链接解析和“手动填写”双入口。
2. 再次创建草稿，填写标题、描述、价格、备注或上传本地媒体。
3. 点击“返回选择方式”，确认对话框说明当前草稿和本地媒体会删除，而运行记录和 AI 配置保留。
4. 点击“取消”，确认所有输入仍在；再次打开对话框并点击“确认返回”。
5. 关闭并重新打开侧边栏，确认已清除草稿和本地媒体不会恢复，AI 配置和运行记录仍在。

## 验证 AI 扩写

1. 完成商品解析或手动填写草稿。
2. 点击“AI 扩写”。
3. 确认按钮立即变为禁用的“AI 扩写中”，状态区域显示正在整理。
4. 请求成功后，确认标题和描述直接写回当前表单，页面中不存在“AI 文案预览”或二次应用按钮。
5. 查看新增数字、事实偏移或高风险声明提醒；继续人工核对生成内容。

AI 只更新标题、描述、警告和更新时间，不应改变价格、原价、发货方式、分类备注或媒体。请求失败时原文案应保持不变。成功写回后仍必须重新检查价格、规格、成色、真伪和售后声明。

## 验证闲鱼登录和填表

1. 由用户本人在 `https://www.goofish.com/` 完成登录。
2. 回到侧边栏，点击“刷新闲鱼登录状态”，确认刷新期间按钮禁用，完成后提示为“闲鱼已登录”。
3. 确认草稿至少包含标题、描述、有效售价和一张已选图片。
4. 点击“填入闲鱼”。
5. 扩展会优先使用当前闲鱼发布页；如果当前不是闲鱼页，则复用已有闲鱼页或打开发布页。
6. 在闲鱼页面检查标题、价格、描述和图片是否正确。
7. 如果草稿包含视频但侧边栏提示“请在闲鱼页面手动上传视频”，由用户手动选择视频；文本和图片填写结果不应回滚。
8. 手动补充分类、规格、运费、交易方式等站点特定字段。
9. 停在最终发布之前，由用户决定是否点击闲鱼“发布”。

如果侧边栏显示“需要登录闲鱼”，点击“打开登录页”并由用户完成登录。扩展不会填写账号密码、处理验证码或自动提交登录。

为保护未发布内容，“打开登录页”只会复用已经存在的闲鱼登录页；如果当前只有闲鱼发布页，扩展会新建登录标签页，不会把发布页导航走或清空其中的表单。

## 验证本地视频（仅人工）

本项目没有执行真实视频、真实 100 MB 文件或真实闲鱼视频上传的自动化测试。以下步骤由用户在本机人工完成：

1. 在草稿中选择一个小型 MP4 或 MOV，确认文件名与大小显示正确，并可预览、移除和替换。
2. 选择不支持的格式或超过 100 MB 的文件，确认原视频保持不变且出现明确提示。
3. 关闭并重新打开侧边栏，确认视频元数据和 IndexedDB 文件仍可读取。
4. 在真实闲鱼发布页点击“填入闲鱼”，核对视频控件是否收到文件；若页面控件不兼容，确认文本和图片仍已填入，侧边栏明确提示手动上传视频。
5. 手动选择视频后继续检查页面，但不要让扩展或验证脚本点击最终“发布”。最终发布只能由用户本人决定并点击。

## 验证运行记录

1. 依次完成商品解析和 AI 扩写，再打开“运行记录”。
2. 确认外层主标题分别使用解析当时或 AI 写回后的商品标题，而不是内部消息类型。
3. 点击记录，确认可展开来源链接、标题、售价、描述、发货方式、分类备注、已选图片数、视频名称、警告、结果或失败原因。
4. 确认分享短链记录详情显示已脱敏的提交来源链接；在扩展开发者工具中确认同一快照还保存最终规范链接。复制或新窗口打开只允许 HTTP(S) URL。
5. 返回商品整理页修改或删除当前草稿，再检查旧记录，确认历史快照没有随当前草稿改变。

## 自动化验证

运行全部静态检查、单元测试和生产构建：

```bash
pnpm check
```

运行隔离端到端测试：

```bash
pnpm test:e2e
```

首次运行 Playwright 且本机没有对应 Chromium 时，先执行：

```bash
pnpm exec playwright install chromium
```

端到端测试使用：

- 独立临时 Chromium Profile
- 匿名淘宝、京东商品夹具和受控的本地短链多段导航夹具
- 本地 OpenAI 兼容夹具接口
- 模拟的闲鱼未登录页和发布页
- 发布按钮点击计数断言

测试覆盖 AI 加载后直接回填、步骤 `02` 与返回初始态、登录刷新、运行记录详情、两张图片批量上传/预览/恢复、分享文案、短链最终 URL、错误页拒绝、图片填表和最终发布按钮点击次数为 0。短链夹具由 Playwright 预先创建受控页面，并以 `route.fulfill` 提供每一跳内容，不访问真实短链或商品站点。

端到端自动化不上传视频，也不创建真实 100 MB 文件。现有轻量单元测试只验证媒体模型和边界逻辑；真实视频上传按“验证本地视频（仅人工）”执行。自动化结果只能证明夹具环境中的安全边界，不能替代真实站点的人工兼容性检查。

当前无头测试直接打开扩展内部的 `sidepanel.html`，测试专用 Manifest 也会预授权淘宝、京东和本地夹具来源。以下两项必须在日常 Chrome 中人工检查：

- 点击扩展工具栏图标后，是否打开 Chrome 原生 Side Panel。
- 首次请求商品、AI 或图片来源权限时，允许与拒绝两条路径是否都给出正确结果，且拒绝后草稿不丢失。

## 打包验证

执行：

```bash
pnpm build
```

检查以下两个产物：

```text
dist/xianyu-assistant-0.1.0-chrome.zip
dist/xianyu-assistant-0.1.0-chrome.crx
.output/chrome-mv3/
```

`pnpm build` 会生成 CRX、Chrome 应用商店 ZIP，以及 WXT 本次构建使用的生产解压目录 `.output/chrome-mv3`。CRX 是由本机 Chrome 打包的扩展文件，ZIP 是 Chrome 应用商店上传包；解压内容应包含 `manifest.json`、`background.js`、`sidepanel.html`、内容脚本和图标。`pnpm build` 不会把解压目录复制到 `dist`，需要稳定的 `dist/xianyu-assistant-unpacked` 时执行 `pnpm build:unpacked`。

首次构建还会生成：

```text
.keys/xianyu-assistant.pem
```

这是 CRX 私钥，用于让后续版本保持相同扩展 ID。目录已被 Git 忽略，但仍应单独安全备份。不要将 PEM 文件提交到仓库、Issue、聊天或网盘公开链接。丢失私钥后重新生成的 CRX 会使用新的扩展 ID。

可以检查 CRX 文件头：

```bash
xxd -l 16 dist/xianyu-assistant-0.1.0-chrome.crx
```

正常输出应以 `Cr24` 对应的十六进制 `4372 3234` 开头。

如果 Chrome 安装在非标准路径，可以执行：

```bash
CHROME_BINARY="/完整路径/Google Chrome" pnpm build
```

需要特别区分：

- 普通 macOS 和 Windows Chrome 只允许用户直接安装由 Chrome 应用商店托管并签名的扩展，本地生成 CRX 不会绕过该限制。
- 本地 ZIP 不能直接安装，也不能在“加载已解压的扩展程序”窗口中选择。
- 本地开发请加载 `dev-dist/xianyu-assistant-unpacked`。
- 生产版解压检查请先执行 `pnpm build:unpacked`，再加载 `dist/xianyu-assistant-unpacked`。
- 面向其他普通 Chrome 用户分发时，将 ZIP 上传 Chrome 应用商店，通过商店安装。

如需检查生产 Manifest：

```bash
pnpm build:unpacked
cat dist/xianyu-assistant-unpacked/manifest.json
```

生产构建的固定站点权限应只有闲鱼 `https://www.goofish.com/*`；商品、AI 和图片来源通过运行时可选权限授权。端到端构建目录 `.output/chrome-mv3-e2e` 仅用于本地夹具测试，不可作为生产包分发。

## 常见问题

### 点击扩展图标没有打开侧边栏

- 确认 Chrome 版本不低于 116。
- 在 `chrome://extensions` 检查扩展是否启用、是否有错误。
- 重新加载扩展后刷新相关商品页和闲鱼页。

### 无法在目录选择窗口中选择开发扩展

- 执行 `pnpm dev` 后，选择可见的 `dev-dist/xianyu-assistant-unpacked`。
- 不要选择 `dev-dist` 根目录；被选择的目录中必须直接包含 `manifest.json`。
- “加载已解压的扩展程序”不能选择 CRX 或 ZIP 文件。

### 修改代码后开发扩展没有变化

- 确认启动 `pnpm dev` 的终端仍在运行。
- 正常情况下终端会显示 `Changed`，随后显示热更新或 `Reloaded extension`。
- 如果修改的是商品页或闲鱼内容脚本，扩展重新加载后可能还需要刷新对应网页。
- 不要执行一次 `pnpm build:unpacked` 后把它当作实时开发目录；生产解压目录不会监听源码。

### 构建时提示找不到 Chrome

- 确认本机已经安装 Google Chrome。
- 非标准安装路径使用 `CHROME_BINARY` 指定可执行文件。
- macOS 常见路径是 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。

### 商品解析后没有图片

- 确认来源页面中的图片已经加载。
- 检查图片域名授权是否被拒绝。
- 某些站点使用临时签名、防盗链或异步数据，扩展可能只能解析标题和价格。

### 图片无法填入闲鱼

- 仅支持 JPEG、PNG 和 WebP。
- 单张图片不得超过 10 MB。
- 每次最多处理 9 张图片，原始图片数据总量不得超过 20 MB。
- 图片服务器必须允许当前浏览器访问，并返回正确的 `Content-Type`。

### 闲鱼字段没有全部填写

- 闲鱼页面结构可能已经变化。
- 侧边栏会显示部分填写结果，运行记录中会保留脱敏错误。
- 刷新闲鱼发布页并重新加载扩展后再试；仍失败时需要更新选择器并重新回归。

### API Key 是否安全

API Key 使用扩展本地存储，不写入 Git 仓库，运行日志会脱敏。但本地存储不是专用密码保险箱：任何能访问当前操作系统用户或 Chrome Profile 的人都可能间接获得数据。不再使用时应移除扩展或清除扩展数据，并在服务商后台轮换密钥。

## 人工验收记录建议

每次真实站点回归建议记录：

- Chrome 版本
- 扩展提交哈希
- 商品平台与页面类型
- 解析字段及缺失字段
- AI 服务供应商和模型，不记录 API Key
- 闲鱼登录检测结果
- 成功填入字段与跳过字段
- 视频文件类型、大小、是否自动填入；未自动填入时是否出现人工上传提示
- 最终发布是否保持人工操作

只有在真实站点逐项检查后，才能写成“真实淘宝、京东或闲鱼页面已验证”。
